# card-deletion-api Specification

## Purpose

Серверная API-спецификация для удаления карточек на Express: маршруты, статус-коды, форматы ответов, обработка ошибок.

## ADDED Requirements

### Requirement: Удаление карточки через DELETE /cards/:id

Сервер SHALL обрабатывать запрос `DELETE /cards/:id`, извлекая идентификатор из пути (`req.params.id`), удалять карточку из хранилища и отвечать `204 No Content` без тела.

#### Scenario: Удаление существующей карточки

- **WHEN** клиент отправляет `DELETE /cards/<id>` с идентификатором существующей карточки
- **THEN** сервер удаляет карточку из хранилища и отвечает `204 No Content` без тела

#### Scenario: GET не возвращает удалённую карточку

- **WHEN** клиент удалил карточку и затем отправляет `GET /cards`
- **THEN** сервер возвращает список карточек без удалённой

### Requirement: Удаление несуществующей карточки

Сервер SHALL отвечать `404 Not Found` с JSON-телом `{"error": "..."}` при попытке удалить карточку, которой нет в хранилище. Данные не меняются, сервер не падает.

#### Scenario: Удаление несуществующей карточки

- **WHEN** клиент отправляет `DELETE /cards/<id>` с идентификатором, которого нет в хранилище
- **THEN** сервер отвечает `404` с телом `{"error": "..."}`, данные не меняются

### Requirement: Неизвестный маршрут возвращает JSON

Сервер SHALL отвечать `404 Not Found` с JSON-телом на любой запрос к неизвестному маршруту.

#### Scenario: Запрос на неизвестный маршрут

- **WHEN** клиент отправляет запрос на любой маршрут, не определённый на сервере
- **THEN** сервер отвечает `404` с JSON-телом, не HTML

### Requirement: Неожиданная ошибка возвращает JSON

Сервер SHALL отвечать `500 Internal Server Error` с JSON-телом при неожиданных ошибках в обработчиках.

#### Scenario: Неожиданная ошибка в обработчике

- **WHEN** в обработчике маршрута происходит необработанное исключение
- **THEN** error-middleware (четыре параметра: `err, req, res, next`) отвечает `500` с JSON-телом

## Out of Scope

- Изменение клиентского кода (`client/`)
- Подключение внешней базы данных — данные остаются в переменной в памяти

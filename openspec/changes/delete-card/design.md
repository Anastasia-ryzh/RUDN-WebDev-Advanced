## Context

Проект использует React + TanStack Query для управления состоянием сервера, json-server в качестве mock API (`db.json`). Создание карточки уже реализовано через `useMutation` в `NewCardForm` с инвалидацией кеша `["cards"]` после успешной мутации. Бэкенд (json-server) автоматически поддерживает `DELETE /cards/:id`.

## Goals / Non-Goals

**Goals:**
- Добавить кнопку удаления карточки в UI
- Реализовать API-функцию `deleteCard(id)` в `client/src/api/cards.ts`
- Удалить карточку из UI после успешного ответа сервера

**Non-Goals:**
- Подтверждение удаления через модальное окно (достаточно прямого клика)
- Анимация исчезновения карточки
- Drag-and-drop и сортировка
- Удаление нескольких карточек одновременно

## Decisions

### Решение 1: Позиция кнопки удаления

**Выбрано:** Кнопка удаления внутри компонента `BoardCard`, справа от названия карточки.

**Альтернативы:**
- Отдельная панель действий вне карточки — усложняет UI, не нужно для одной операции
- Контекстное меню по правому клику — избыточно для единственного действия

### Решение 2: Паттерн удаления

**Выбрано:** `useMutation` с `mutationFn: deleteCard`, инвалидация `["cards"]` в `onSuccess` — аналогично `NewCardForm`.

**Альтернативы:**
- Оптимистичное обновление — не требуется, карточек мало, задержка незаметна
- `onSettled` вместо `onSuccess` — избыточно, при ошибке достаточно оставить карточку на месте и показать ошибку

### Решение 3: Обработка ошибок

**Выбрано:** `console.error` + `alert` при ошибке удаления.

**Альтернативы:**
- Toast-уведомления — требуют дополнительного компонента, который в проекте отсутствует
- Inline-ошибка под карточкой — усложняет layout

## Risks / Trade-offs

[Risk] Пользователь может случайно удалить карточку одним кликом → [Mitigation] В рамках этого тикета подтверждение не требуется; при необходимости можно добавить в будущем

[Risk] Быстрое многократное нажатие на кнопку удаления → [Mitigation] `useMutation` по умолчанию блокирует повторные вызовы во время выполнения мутации (`throwOnError` по умолчанию `false`, `onMutate` блокируется пока `isPending`)

## Migration Plan

Изменение не требует миграции данных — json-server поддерживает `DELETE /cards/:id` из коробки. Достаточно добавить клиентский код.

## Open Questions

Нет. Все технические решения определены на основе существующего паттерна `NewCardForm`.
